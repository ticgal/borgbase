Borgbase 3.0.0 — QA checklist (GLPI 12)

How to fill in: mark Result with OK or KO only. Use Comments for the error message, a screenshot reference or a note on what went wrong.

Before starting: a BorgBase account with at least two repositories and a read-only API key; one GLPI computer whose name is exactly the name of one repository; one computer whose name matches none; three users: an administrator, a technician of another entity, and a user with read-only Borgbase rights. Every check below only reads the BorgBase account. Items marked [live write] create or delete records in GLPI; the [destructive] section at the end removes the plugin data.

Known limitations

  • Opening the Borgbase tab of an unlinked computer links it automatically when its name matches a repository and the "Computer name matches exactly with repository name" option is enabled. This is by design.
  • The plugin uses one BorgBase account for the whole GLPI instance: the repository list and the account usage cards are the same in every entity.
  • A BorgBase endpoint on a private network address requires an entry in GLPI's config/local_define.php (see README); without it the connection is reported as failed.
  • New Borgbase rights are not granted to any profile on install; an administrator has to grant them (check 8).
